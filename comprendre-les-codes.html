Comprendre les codes inerWeb

Il y a trois codes différents dans inerWeb, et ils ne servent pas du tout à la même chose. Cette page dit lequel fait quoi, qui le détient, et comment récupérer le travail de vos élèves. Comptez cinq minutes.

Les trois codes, en un tableau

Le codeIl sert àQui l'aÀ quoi il ressemble
Votre code enseignant Ouvrir votre espace : les documents, et le droit d'ouvrir des séances à vos classes. Vous seul. Il porte votre nom. Une longue chaîne, ~330 caractères. Elle se colle, elle ne se tape pas.
Le lien de séance Ouvrir un contenu à une classe, pour une durée que vous fixez. Toute la classe. C'est le même pour tout le monde. Un lien, et son QR code à projeter.
Le code d'élève Dire qui est l'élève, pour que vous sachiez qui a fait quoi. Un par élève. Vous les distribuez. Quatre caractères, du type 7K2M.

Un quatrième code circule dans l'autre sens : le code de restitution, que l'élève obtient à la fin et vous renvoie. C'est lui qui porte ses résultats. Il fait une trentaine de caractères.

Pourquoi ce n'est pas un simple mot de passe

Un mot de passe partagé, ça circule. Au bout d'un an, tout le monde l'a, et vous ne pouvez plus le retirer sans embêter ceux qui travaillent bien.

Ici, chaque code est fabriqué pour une personne et signé. Trois conséquences concrètes :

  • Votre code porte votre nom — les documents que vous ouvrez l'affichent en filigrane. Si un document se retrouve ailleurs, on sait par quel accès il est passé.
  • Il expire au bout d'un an. Pas « une date qu'on peut contourner en reculant l'horloge » : à la rentrée, les contenus sont rechiffrés avec la clé de l'année, et l'ancien code ne sait plus rien ouvrir. Vous en recevez un nouveau.
  • Vous fabriquez vos séances vous-même, sans jamais nous redemander quoi que ce soit — et sans pouvoir fabriquer de code enseignant pour quelqu'un d'autre.

Tout se vérifie dans votre navigateur. Aucun code ne part sur internet, il n'y a pas de compte à créer, pas de mot de passe à retenir, et aucun serveur ne sait ce que vous faites.

Le chemin complet d'une séance

  1. Vous demandez un accès Une fois par produit, une fois par an. Vous recevez votre code enseignant par courriel.
  2. Vous le collez sur la page « Activer » Une seule fois sur cet appareil. Il y reste rangé.
  3. Vous ouvrez une séance Un nom (« CAP IFCA — groupe A »), une date de fin, un nombre d'élèves. Vous obtenez un lien, un QR code, et la liste des codes d'élève.
  4. Vous distribuez Le lien ou le QR pour entrer, et à chacun son code de quatre caractères. La liste s'imprime et se découpe. Notez en face de chaque numéro le nom de l'élève : cette feuille reste chez vous.
  5. L'élève travaille Il ouvre le lien, tape ses quatre caractères, et c'est tout. Aucun compte, aucun nom demandé, rien à installer.
  6. Il vous renvoie son code de restitution Une trentaine de caractères, obtenus en fin de séance. Par message, par l'ENT, par courriel — le canal que vous utilisez déjà.
  7. Vous dépouillez Vous collez tous les codes reçus d'un coup dans la page des séances, et vous obtenez le tableau de la classe : score, réussite, durée, par élève.

Ce que le système protège, et ce qu'il ne protège pas

Autant le dire une fois pour toutes, plutôt que de vous laisser le découvrir.

Ce qui est vrai

  • Les contenus publiés ne sont lisibles nulle part en clair.
  • Chaque accès porte un nom, et le filigrane le rappelle.
  • Tout expire au bout d'un an, pour de bon.
  • Un code de séance ne peut pas survivre à l'accès qui l'a signé.
  • Un résultat modifié en route est détecté et écarté.
  • Un résultat venant d'une autre séance est refusé.
  • Aucune donnée d'élève ne quitte votre salle. Aucun nom n'est demandé nulle part.

Ce qui n'est pas vrai

  • Ça n'empêche pas quelqu'un d'enregistrer ce qu'il voit à l'écran. Aucune technique ne le fait, nulle part.
  • Ça ne referme pas une copie déjà prise.
  • Un lien de séance est un lien : publié sur un forum, il fonctionne pour tout le monde jusqu'à sa date de fin.
  • Le code d'élève n'est pas une identité : un élève peut prendre le numéro d'un autre s'il connaît son code.
  • Un élève peut gonfler son score. Le navigateur corrige les réponses, donc il les connaît.
Donc : ces résultats servent à suivre, pas à noter. Ils vous disent qui a travaillé, qui a coincé, sur quoi revenir à la séance suivante. Ils ne sont pas assez sûrs pour une note qui compte au bulletin — et un élève qui gonfle son score se prive surtout lui-même. Une évaluation qui compte se fait devant vous.

Les questions qui reviennent

J'ai perdu mon code enseignant.

Redemandez-en un. L'ancien reste valable jusqu'à sa date — hors ligne, on ne peut pas révoquer un code déjà envoyé ; c'est la rentrée suivante qui le referme.

Je change d'ordinateur.

Recollez votre code sur le nouveau. Il est rangé dans le navigateur, pas dans un compte. Sur un poste partagé, retirez votre accès en partant.

Un élève n'a pas de téléphone pour scanner le QR.

C'est prévu, et c'est même pour ça que le système est fait ainsi : le lien s'envoie aussi par l'ENT ou par écrit, et le code d'élève ne fait que quatre caractères — pas un lien de quatre cents à recopier.

Deux élèves ont le même code.

C'est rare, mais possible. Dans ce cas la page vous prévient, et ce code ne désigne personne — plutôt que de faire travailler un élève sous le numéro d'un autre en silence. Refabriquez la séance : elle tire de nouveaux codes.

J'ai plus de 100 élèves sur une séance.

La limite est fixée à 100 à titre provisoire. Elle n'est là que pour borner le système tant qu'on découvre l'usage réel. Demandez-la plus haute, c'est un nombre à changer.

Un code de restitution a été refusé.

Il vient d'une autre séance, ou il a été abîmé en chemin — un caractère perdu au copier-coller suffit. Redemandez-le à l'élève plutôt que d'essayer de le deviner.

Est-ce que je peux voir ce qu'un élève a fait chez lui, en direct ?

Non. Rien ne remonte tout seul : il n'y a pas de serveur, c'est ce qui garantit qu'aucune donnée d'élève ne circule. L'élève vous envoie son code quand il a fini.
